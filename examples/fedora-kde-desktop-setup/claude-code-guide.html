01Install

The native installer self-updates in the background, so it's the path of least maintenance.

MethodCommandUpdates
Native (recommended)curl -fsSL https://claude.ai/install.sh | bashAutomatic
npmnpm install -g @anthropic-ai/claude-codeManual (claude update)
Linux packagesdnf / apt / apkManual, via package manager
Homebrewbrew install --cask claude-codeManual (brew upgrade)
Verify: claude --version confirms the install; claude doctor runs a full health check on the binary, config, and permissions if anything seems off.

02Starting sessions

Run claude in any directory to open an interactive session scoped to that folder — it becomes the project Claude reads and edits in.

FlagEffect
-p, --printRun one prompt non-interactively and exit — scripting-friendly.
-c, --continueResume the most recent conversation in this directory.
-r, --resumeOpen the session picker to choose which past conversation to reopen.
-n, --name <name>Name the session on creation, instead of an auto-generated suffix.
--model <model>Override the default model for this run (alias like opus, or a full model ID).
--permission-mode <mode>Start directly in default, auto, plan, or bypassPermissions.
--add-dir <path>Bring an extra directory into scope alongside the working directory.
--settings <file|json>Layer in settings for just this run, on top of the normal precedence chain.
--output-format <fmt>text, json, or stream-json — for piping output to other tools.
Combine freely: claude --model opus --permission-mode plan "outline the migration" starts a plan-mode session on Opus without touching your defaults.

03Conversations & resume

Every session is written to disk as it happens — nothing to save manually. Locally that's ~/.claude/projects/<project>/<session-id>.jsonl, kept for 30 days by default (cleanupPeriodDays in settings changes that).

CommandWhat it does
claude --continueJump straight back into the last conversation in the current folder.
claude --resumeOpen the picker across this project's sessions.
claude --resume <name|id>Reopen a specific session directly, by name or ID, from anywhere.
/resumeSwitch conversations without leaving the CLI.

Inside the picker

↑ / ↓

Move through sessions, newest first.

Space

Preview a session's content before committing.

Enter

Reopen the highlighted session.

Ctrl+R

Rename the highlighted session in place.

Ctrl+A

Widen the list to every project on the machine, not just this one.

/ (type)

Filter the list as you type.

Resuming restores the full transcript, the model in use, and the permission mode you left it in. Name a session early — claude -n auth-refactor, or /rename mid-session — so it's recognizable in the picker weeks later instead of a two-word auto-generated tag.

06Permission modes

The mode decides which actions Claude just does versus which it checks with you first. Cycle live with Shift+Tab, or fix one at launch with --permission-mode.

ModeBehavior
defaultPrompts before most edits, shell commands, and network access. Maximum oversight.
autoActs on routine work on its own; a fast secondary check reviews higher-risk actions (deletions, credential access, sensitive paths) instead of interrupting you for every one.
planProposes a multi-step approach first; you approve or decline the whole plan before anything runs.
bypassPermissionsSkips every check, including destructive ones. For unattended, trusted scripts only.
This machine's ~/.claude/settings.json now sets permissions.defaultMode to auto — sessions in every project start in that mode unless a project overrides it.

07Settings & CLAUDE.md

Settings stack from broad to specific — a narrower file wins where they conflict.

  1. Managed settings — set by an organization; overrides everything.
  2. --settings flag — this run only.
  3. .claude/settings.local.json — per-project, personal, not committed.
  4. .claude/settings.json — per-project, shared with the team via git.
  5. ~/.claude/settings.json — this machine's defaults, applied everywhere else falls through.

CLAUDE.md

A plain-markdown file Claude reads automatically at the start of every session in that project — conventions, architecture notes, gotchas, anything worth knowing going in. A project's own copy lives at its root (for example ~/Workspaces/AI+PC/CLAUDE.md); ~/.claude/CLAUDE.md applies globally, to every project on this machine. Edit either with /memory, or scaffold the project one with /init.

08MCP — Model Context Protocol

A standard way for Claude Code to talk to something outside the conversation — a database, an internal API, a ticketing system — as tools it can call mid-session, rather than you pasting data back and forth by hand.

How a server connects

Each server is registered once, then shows up as a set of callable tools for the rest of the session. Registration is a name, a transport, and how to reach it:

TransportFitsAdd with
stdioA local process launched and piped to directlyclaude mcp add --transport stdio <name> -- <command>
httpA remote service at a fixed URLclaude mcp add --transport http <name> <url>
sseServer-sent events — older, largely superseded by httpclaude mcp add --transport sse <name> <url>

Managing servers

claude mcp listSee what's registered.
claude mcp get <name>Inspect one server's configuration.
claude mcp remove <name>Deregister it.
/mcpCheck connection status and browse tools from inside a session.

Scope

A server can be registered just for you (local/user) or shared with a team through a .mcp.json checked into the project (project) — same mechanism as settings, narrower scope wins.

MCP is a protocol, not a product: it doesn't come with servers built in. Deciding whether to connect one is about whether something outside the conversation needs to be reachable from it — not covered further here.

09Plugins

A plugin is a packaged bundle — skills, agents, hooks, an MCP server, or a combination — distributed and versioned as one unit, instead of copied file by file into .claude/.

What's inside one

  • .claude-plugin/plugin.json — name, version, author.
  • skills/ — one folder per skill, each with a SKILL.md.
  • agents/, hooks/, .mcp.json — same shapes as their project-level equivalents, just packaged.

Working with them

/pluginBrowse, install, enable, or disable — from inside a session.
claude plugin listSee what's installed.
claude plugin remove <name>Uninstall.
--plugin-dir <path>Load a plugin from a local folder for just this session — for building or testing one.

Plugins come from marketplaces — a git repository listing available plugins, registered with /plugin marketplace add owner/repo. A plugin installs against a specific marketplace, so which ones you have access to depends on which marketplaces are registered — that's a browsing decision inside /plugin, not something fixed by this guide.

When something's wrong

  • /doctor or claude doctor — health check of the install and config.
  • claude --debug — verbose logging for a single run.
  • /status — a quick read on model, mode, and token usage right now.
Reflects this machine's Claude Code install. Flags and commands can change between versions — /help and claude doctor always show what your current build actually supports.
